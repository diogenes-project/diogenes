- **attach CLI stderr log handler so pre-pipeline errors surface (#154)**

- **disposition every raw search result, validate invariant (#163)**
R0063/Q001/S01 had 5 raw results, 4 in selected_sources, 0 in
rejected_sources, and 1 URL
(https://link.springer.com/article/10.1007/s10664-026-10858-8)
appearing in neither — the disposition-accountability invariant
was silently broken. The invariant:

    len(selected for search_id) + len(rejected for search_id)
    == total_returned (per search, per item)

Three root causes the pipeline was silently dropping results:

1. Relevance-threshold drop without a rejected_sources entry —
   results that scored below the threshold were aggregated into a
   single pipeline-note count but never recorded per-search.
2. URL dedupe across searches without a bookkeeping trail — when
   a later search re-discovered a URL, the earlier search "lost"
   the entry without explanation.
3. Scorer no-show — the specific R0063 case. A raw result that
   never reached the scorer (content-extraction failure, row
   index mismatch, etc.) fell off the end of the pipeline
   entirely, accounted for nowhere.

All three now write a rejected_sources entry carrying a structured
`reason` field:

    below_relevance_threshold  — scored, below cutoff
    duplicate_url              — already covered by another search
    scorer_did_not_score       — scorer didn't return a verdict

The enum is tight on purpose; see the description in
search-results.schema.json. Adding a new reason is a deliberate
schema change, not a free-form annotation.

validate_search_results_dispositioning runs at end of step 5 and
asserts the invariant across every (item, search_id) pair. Raises
a structured failure when it breaks so a future regression becomes
visible immediately instead of at renderer time.

- **walk up parent dirs looking for .env (#155)**
load_config() now searches for .env starting at the current working
directory and walking up parent directories. The walk is bounded at a
.git boundary (file or directory), the user home directory, or the
filesystem root, whichever is hit first. This lets dio be invoked from
any subdirectory of its dev tree (including .worktrees/issue-N-slug/)
without needing to cd to the repo root to locate keys.

An explicit [env] dotenv_path in .diorc still wins and disables the
upward search, preserving the ability to point at a specific file.
Priority order is otherwise unchanged: real env vars > nearest .env >
./.diorc > ~/.diorc.

## Features

- **v1.0.0 — initial public release**
Claude Code plugin implementing a unified research methodology combining
nine intelligence and scientific frameworks (ICD 203, GRADE, PRISMA,
Cochrane, IPCC, Chamberlin/Platt, ROBIS, NAS, CONSORT) into a 14-step
evidence-based process.

Two modes: claim verification and query answering. Anti-sycophantic
behavioral constraints. Five-domain self-audit including source-back
verification. Default portable markdown output format.

- **Rule 6 — required sections are minimum, not maximum**
Explicitly encourage agents to add comparison tables, unexpected
patterns, connections, and additional observations beyond the
required structure. The spec ensures consistency; anything beyond
it adds value. Don't suppress interesting findings.

- **unify claim and query prompts into single research.md**
Merged claim.md and query.md into research.md. Both modes now in one
file with conditional sections for mode-specific behavior (hypothesis
framing, search strategy, assessment approach, report structure).
Eliminates duplication and inheritance complexity. One file to maintain,
one file to test, one file to share.

- **add axiom support — declared facts assumed true during research**
Three input types: axioms (assumed true), claims (tested), queries
(answered). Axioms function as constraints that frame the investigation
without being tested. If evidence contradicts an axiom, it is reported
but the axiom is not overridden. Inspired by Choe's ICD 203 approach
where researcher-provided facts must be assumed true. This formalizes
the mechanism and makes the distinction between axioms and embedded
assumptions explicit.

- **add standalone prompt and HTML output mode**
standalone/research.md is a single-file concatenation of the research
methodology prompt and default output format. Paste into any Claude
interface and go.

- Mode B (web chat): single self-contained HTML with anchor navigation,
  displayed in conversation then offered for download

README updated with standalone usage instructions.

Specific, testable conditions that would warrant re-running research:
named studies, time-based deadlines, data source updates, policy changes,
organizational position changes. Each trigger must be specific enough

Enables automated monitoring of research currency. Standalone regenerated.
